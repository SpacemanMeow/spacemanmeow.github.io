# SpacemanMeow SEO 总览

- **[SEO-PLAYBOOK.md](./SEO-PLAYBOOK.md)** —— SEO 方法沉淀手册：系统化、按分类（技术 / 内容 / 内链 / AI 搜索 / 外部权威 / i18n / 治理）归纳可复用的实践方法，每条标注本站落地状态。**用于长期积累 SEO 方法论。**
- **[SEO-PROGRESS.md](./SEO-PROGRESS.md)** —— SEO 进度跟踪：任务总览（区分一次性 / 长期运营）、已落地明细、待做清单、月度运营规划（§4 checklist 化）。**用于看清哪些已做、哪些没做、按计划滚动。**
- **[SEO-METRICS.md](./SEO-METRICS.md)** —— 核心指标月度报告：每月 GSC/GoatCounter 核心趋势表 + 各月详细分析（已拆出独立维护，便于按月滚动更新）。
- **[SEO-KEYWORDS.md](./SEO-KEYWORDS.md)** —— 跨语言关键词权威库：按「语言 × 词层(Head/Middle/Long-tail) × 优先级(P0/P1/P2)」分组排序，含目标页映射与覆盖状态；新文/改文须基于本库优化文案，并随 Google Play Console / GSC 数据月度维护。**用于决定「写什么、怎么写」。**
- **[SITE-AUDIT.md](./SITE-AUDIT.md)** —— 全站整体教研（校验）规范：大规模改动后的唯一验收标准，含 D01–D20 维度、基线快照、一键静态教研脚本与记录表。**用于回答「改动后整站是否仍然正确」。**
- **[SEO-I18N-PLAYBOOK.md](./SEO-I18N-PLAYBOOK.md)** —— 多语言内容扩展标准流程：新增语言或为某 App 补多语言内容时直接按 12 步执行，含不可协商红线、本地关键词 SOP、页面类型全覆盖清单与验收。**后续所有语言扩展按此规范执行，无需重复说明要求。**
- **[SEO-I18N-PROGRESS.md](./SEO-I18N-PROGRESS.md)** —— 多语言扩展唯一状态源：语言矩阵、页面类型覆盖、posts 清单、校验记录与下一批入口。**用于防止上下文溢出导致内容质量下降或实现方式不一致。**
- **[SEO-GOOGLE-PLAY.md](./SEO-GOOGLE-PLAY.md)** —— Google Play ASO 规范：标题 / 简短说明 / 完整说明的字数、合规表述与发布前校验。**用于写或改商店文案。**


## 使用方式
1. 想了解「某类 SEO 该怎么做」→ 读 Playbook。
2. 想了解「当前进度 / 本月该做什么 / 填台账」→ 读 Progress。
3. 新落地一项方法：在 Playbook 对应分类补方法 + 在 Progress 标 ✅ 并填日期；长期运营项按月执行 Progress 的 §4.1 清单（并勾选 §4.2 当月规划对应月份），数据复盘同步更新 `SEO-METRICS.md` 月度报告。
4. 大规模改动后要验收整站 → 按 `SITE-AUDIT.md` 完整教研一遍并填写教研记录表。
5. 新增语言 / 为某 App 补多语言内容 → 先读 `SEO-I18N-PLAYBOOK.md` §1 与 §3，再读 `SEO-I18N-PROGRESS.md` 的「当前批次」，按批次执行并回填状态。

## 文档更新规则（seo/ 目录统一口径）

> 本规则是 `seo/` 全部文档的写入准绳，**权威落点在此**；`SITE-AUDIT.md` D16 与 `AGENTS.md` §6 引用本规则，不另立口径。

**一句话**：只写有长期价值的内容——**需要沉淀的经验、阶段性重要进展、SOP / 规则**；临时性内容与一次性改动不写入。规则或有价值内容一旦出现，**第一时间同步**，避免遗漏。

### 该写（长期价值）

| 类别 | 例子 | 写入位置 |
|---|---|---|
| SOP / 规则 / 红线 | 新增语言流程、D 维度判定、本文档更新规则本身 | `SEO-I18N-PLAYBOOK.md`、`SITE-AUDIT.md`、本文件 |
| 需沉淀的经验 / 坑 | 反复出现且已定位根因的问题（`page.lang` 选集合、`app_store:` 裸空值等） | 对应 PLAYBOOK 的「避坑 / 已知陷阱」、skill 的 `references/` |
| 阶段性重要进展 | 新语言全量上线、某类内容 5 语对称达成、新维度 / 新门禁上线 | 唯一状态源 `SEO-I18N-PROGRESS.md` / `SEO-PROGRESS.md`；基线数字进 `SITE-AUDIT.md` §8 |
| 优化方案 / 措施与规划 | 新落地或计划落地的 SEO 方法、月度目标 | `SEO-PLAYBOOK.md`、`SEO-PROGRESS.md`、本文件 |

### 不该写（临时性）

- 一次性 bug 修复、格式 / 排版调整、口径一致性修正的**过程与明细**；
- 单批执行的逐文件流水、临时脚本、试错过程、中间产物；
- 已清零的欠账表、历史快照的逐条记录——历史交给 git 与 `SITE-AUDIT.md` §8 的最近基线；
- 临时日志与数据（`seo/data/`、GSC 导出）只作处理中转，不作为文档内容。

### 及时更新（防遗漏）

1. **改规则** → 同一次改动内同步规则文档（`SITE-AUDIT.md` 维度 / 红线、对应 PLAYBOOK、本文件）与 `AGENTS.md` / 对应 skill；**先更新规则再改代码**，最后跑构建 + 审计。
2. **产出有价值内容**（新 SOP、新坑、阶段性进展）→ **当场写入对应位置**，不攒到下次、不依赖会话记忆。
3. **单纯修复 / 调整** → 不新增「已完成优化」条目、不制造第二个状态源；状态只写唯一状态源。
4. **收工自查** → 对照本表确认：本轮①~③类内容是否被漏写、临时流水是否被误写。

## 适用范围与目标
- 站点：spacemanmeow.com，5 语并行（EN 根 + `/zh/` `/id/` `/ms/` `/th/`，均已全量上线，文章 / 应用 / 术语 / 结构页对齐）。所有方法默认**全语言同步**执行；新增语言走 `/<lang>/` 子路径、配 hreflang 与 canonical，URL 不变、不破既有关联。
